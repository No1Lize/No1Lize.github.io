# 架构

## 系统边界

```text
公开来源
  ├─ 公司官网 / 投资者关系 / SEC
  ├─ 金融、创投、科技媒体 / 新浪
  ├─ X 公开资料 / 微信公开索引
  └─ OpenAlex / arXiv
          │
          ▼
GitHub Actions 标准库抓取器
  ├─ 解析、清洗、分类、去重
  ├─ 按来源批次替换
  └─ 数据质量门
          │
          ▼
public/data/articles.json → main → GitHub Pages
```

项目没有服务器、数据库、内部 API、用户身份、管理后台、AI 对话入口或知识图谱。后续数据源只能通过公开方式或明确授权的 API 接入。

## 数据流

1. 抓取器只请求代码和配置中列明的公开来源；
2. 每条记录保存标题、必要短摘要、发布日期、分类、地区、主体、信源等级、平台和原始链接；
3. SEC 同时提取最近申报以及带报告期和表单口径的 Company Facts；
4. URL 规范化后，以来源链接和事件指纹双重去重；
5. 成功来源替换自己的旧生成批次；失败或空来源保留上一版数据；
6. 人工编辑种子永久保留，除非人工删除；
7. 质量门验证最低数量、来源健康度、地区、平台、事件类型、来源层级、集中度、日期和 URL；
8. 质量门失败时不写文件；通过时仅在内容变化后提交；
9. GitHub Pages 从同一 JSON 静态构建并在浏览器中读取。

## 降级

浏览器优先读取 `/data/articles.json`。请求失败时使用构建时打包的同一快照。工作流中任何来源失败不会删除最后一次成功数据；构建失败不会替换上一版 Pages。
