# 科创板招股说明书机构候选审核流程

## 目的

自动 PDF 文本抽取只负责发现候选。对外可见的“已人工核验”状态必须来自版本化审核清单：

```text
config/star_market_investor_reviews.json
```

审核决定会经过同一证据行质量门。人工清单不能绕过名称碎片、发行人自身名称、证据缺失、多值歧义或持股数值冲突。

## 审核键

每条候选在页面和快照中显示稳定审核键：

```text
<companySlug>:<investorId>
```

示例：

```text
cambricon:star-investor-b6cedf2e80327dde6e
```

不得仅凭机构显示名称创建决定，因为不同上市公司中可能出现同名机构，候选 ID 也可能因名称规范化修复而变化。

## 清单格式

```json
{
  "schemaVersion": 1,
  "reviews": {
    "cambricon:star-investor-b6cedf2e80327dde6e": {
      "status": "verified",
      "reviewer": "reviewer-github-handle",
      "reviewedAt": "2026-08-04T08:00:00+08:00",
      "note": "已核对第 74 页股东表，名称及 3.92% 比例一致。",
      "reasons": []
    }
  }
}
```

允许的人工状态只有：

- `verified`：证据页、候选名称及同一行持股字段均已核对；
- `rejected`：确认不是应公开的发行前机构股东候选。

`needs_review` 不写入清单。没有人工决定的机器候选会自动保持该状态。

## 审核步骤

1. 在候选卡片中复制审核键并打开“核对招股书原页”。
2. 确认候选名称确实位于发行前股东或股本结构表，而非正文叙述、管理人介绍或间接持股说明。
3. 确认页面展示的持股数和比例都位于候选名称之后的同一证据行。
4. 需要公开联系字段时，额外核对该联系方式确实属于候选机构，而不是发行人、中介机构或相邻股东。
5. 在审核清单中写入 `verified` 或 `rejected`，填写审核人、时间和说明。
6. 提交后由科创板刷新工作流重新生成快照、运行 Python/TypeScript 测试并构建站点。

## 强制质量门

发布任务会拒绝以下情况：

- 清单键无法匹配当前候选；
- `reviewer` 为空；
- `reviewedAt` 不是 ISO-8601 日期或时间；
- 人工 `verified` 与机器证据质量门冲突；
- 未核验记录仍携带公开联系方式；
- 快照中的审核统计与逐条状态不一致。

清单键失效通常意味着候选名称或 ID 发生变化。此时应重新核对新候选，不应直接复制旧决定。

## 审核边界

“已人工核验”仅表示站内记录与指定招股说明书证据页一致，不表示：

- 机构当前仍持有该公司股份；
- 机构身份、控制关系或工商状态未发生变化；
- 联系方式目前仍然有效；
- 该记录可以替代法律、审计、投资或尽职调查意见。
