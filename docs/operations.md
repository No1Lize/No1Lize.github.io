# 运维

## 任务频率

- GitHub Actions 每两小时执行完整公开情报检查；
- 可手动选择公司、媒体、X、论文、公开索引或 SEC；
- 抓取逻辑/来源配置更新时自动执行一次完整刷新；
- 无内容变化时不提交。

## 失败处理

- 网络请求最多重试三次并使用短指数退避；
- 单个来源失败不阻塞其他来源；
- 失败或空来源不删除上一版成功数据；
- 所有候选数据必须先通过质量门，失败时不覆盖 JSON；
- Pages 构建失败不替换线上上一版。

## 观察指标

Actions 日志记录各来源的耗时、扫描量、接收量和错误。`articles.json` 保存稳定的来源状态与质量门结果，但不保存每次运行的耗时，避免产生无意义提交。

重点检查：

- `articleCount`；
- 健康来源数量；
- 中国、美国、全球记录分布；
- 信源层级、平台和事件类型覆盖；
- 无效日期或链接数量；
- 单一来源最高占比；
- URL 去重结果。

## 恢复

`articles.json` 的每次变化均保存在 Git 历史中。误抓取时回退对应数据提交；修复抓取器后手动运行 **Refresh public intelligence**。不要手工删除失败来源的上一版数据。
